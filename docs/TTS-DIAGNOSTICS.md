# Диагностика озвучки Android

В приложении есть локальный журнал для поиска ошибок между интерфейсом, JavaScript-мостом и системным Android TTS.

## Как сохранить журнал сбоя

1. Откройте **Слушать → Настройки плеера → Диагностика озвучки**.
2. Нажмите **Очистить**, закройте журнал и повторите запуск озвучки до проявления сбоя.
3. Снова откройте журнал и нажмите **Скопировать**.
4. Передайте скопированный текст вместе с описанием: нажимали ли вы «Слушать» или круглую кнопку Play, включён ли автозапуск, и началось ли чтение со звуком.

## События

- `autostart.*`, `player.*`, `queue.ready` — состояние интерфейса, выбранная позиция и размер подготовленной очереди.
- `native.enqueue`, `native.event`, `native.first_start`, `native.start.timeout` — отправка фраз Android и ответы, вернувшиеся в WebView.
- `engine.init`, `speak.request`, `speak.waiting_for_engine`, `speak.submitted`, `speak.on_start`, `speak.on_done`, `speak.on_stop`, `speak.on_error` — состояние системного TTS-движка.
- В событиях `speak.*` и `native.*` одинаковый ID связывает одну фразу между JavaScript и Android.

В журнал не попадает сам текст книги. Записываются только ID фразы, её ссылка в книге, номер предложения, язык, длина строки, выбранный движок и коды/типы ошибок. Журнал остаётся на устройстве, хранит последние 400 событий каждой стороны и очищается из того же окна.
